# 停止后编辑

原生 DSH 和 MiniMax M3.1/M3 对话的输入框旁提供“停止后编辑”。选择一条已经发送的用户消息后，套件停止当前工作并等待空闲，回退到该消息之前，创建“编辑分支”。点击“打开编辑分支”会使用官方导航打开正常会话，空输入框会填入原文本；首条消息的空分支也能打开，原对话重载后入口仍保留。原对话保留供查看。只有再次点击发送才调用模型。

其他 Harness 不渲染任何入口。当前选择与已有 Runtime 所属 Harness 不一致时也不提供编辑。

## 入口状态

入口只在真的有可选消息时出现，但它不会无解释消失：

- 首批 Harness 首轮还没有任何已发送消息时显示“暂无消息”；仍在运行时显示“当前正在运行”，两者都按 Host 报告的 `busy` 与真实历史判断，不猜消息身份，不轮询，也不自动停止发送。
- 首批 Harness 但运行时尚未就绪（例如 MiniMax 未建立连接）时，显示 Host 给出的原因，而不是一句笼统的“尚未提供”。
- 被一次未落定的编辑阻断时显示阻断原因，并只提供只读的“重新读取会话历史”。
- 不在首批范围内的 Harness 一个字段都不设置，客户端因此不渲染任何内容。

## 可选消息与禁用原因

- 缺少 operation 与原生用户消息精确映射的旧消息一律禁用，并显示原因；不会按文本或时间猜配。
- 带附件的消息在改动会话之前就禁用并显示原因：官方没有公开的附件回填接口。
- MiniMax 需要带有 OPL 会话历史扩展 v1 的候选 CLI。套件通过真实 Runtime 的用户消息身份回退上下文，且明确传入 `rewindTurnDiff=false`。

## 回退与原文草稿

- 回退后原文回到普通输入框，由用户再次发送才启动一次模型请求。原生 DSH 的原文落在新分支会话上，MiniMax 落到打开的分支；编辑前的原对话不会填入新分支的草稿。
- 输入框里已经有草稿时不覆盖：用户正在写的内容一个字都不动，原文保留在“待填原文”里，可以查看；清空输入框后才会填回，并把这次落地确认给 Host。
- 待填原文是 Host 的持久事实，进程重启或重新打开会话后仍能取回。

## 失败与恢复

- 回退请求失败时，先按 Host 的持久状态重新读取一次，再显示固定诊断；同一条消息的重试复用同一个请求身份，Host 只会真正回退一次。
- 结果不确定的编辑不会被重发、不会被解除阻断，也不会被描述成“会话没有被改动”。此时入口收起，唯一可执行的动作是只读的重新读取；核对真实历史之后入口才会恢复。
- 清除待填草稿的公开响应里 `acknowledged` 为 `false`、响应形状不认识、或这次调用抛错，都按“没有确认”处理并给出同一条固定诊断；输入框里的原文不会被撤销，持久草稿留在 Host，重启后可能再次出现。
- 提示与原文只回传给它们真正所属的会话与仍然打开的那段界面：组件已经卸载、或用户已经切到别的会话时，晚到的回退结果不会再写输入框、不会确认草稿、也不会打开分支；原文留在 Host 的持久草稿里，等下一次安全恢复时重新读取。
- 界面只显示固定诊断，不反射 Runtime 或底层库的原始异常文本。

## 限制

- 附件无法自动恢复，只能在改动之前拒绝。
- 无法完整复制权限的 custom 对话会拒绝；先选择内置权限选项。
- 本流程只改变对话上下文，已经修改的磁盘文件保留，不做任何文件撤销，也不改动 Runtime 本身。
- 能力判定以 Runtime 自己的公告为准；未公告扩展时一律判为不可用，不猜测可用。
