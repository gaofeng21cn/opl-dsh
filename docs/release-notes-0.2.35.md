本版跟随官方 DSH `0.2.1-rc.2` 更新依赖与运行时接口，并把执行相关设置合并为一个入口。对外壳、Agent 循环和会话格式的维护边界保持不变。

### 变更

- 设置导航由 10 项收敛为 8 项。“执行引擎”“执行组合”和“工具审批”合并为“执行与组合”：常用区直接管理模型、Harness 与权限绑定；低频的执行程序、版本、路径、独立网络代理和 Auto Review 收纳在同一页的折叠区。原有保存、校验、失败保留和连接代次规则不变。
- 跟随官方 DSH `0.2.1-rc.2` 更新 Cordis `4.0.5`、Schemastery `3.18.5` 和完整官方 API cohort。内部 Remote 调用按新版接口显式携带官方 Peer；控制桥与后台调用沿用调用者身份，无法取得 Peer 时拒绝执行。
- 适配新版官方 Client 的模块加载边界：增强包保留官方运行时为 peer，并在构建时内联新版生成的 Typert `remote-info` 纯入口，避免插件在加载阶段因模块表缺少该入口而中断。
- 将官方存储域依赖的 Zod 固定为 `4.4.3`，避免根项目安装更高版本后出现两套 Zod 类型与 Schema 身份。

### 已知限制

- 官方桌面仍处于 `0.2.1-rc.2` 候选阶段；Release 记录实际验收的候选版本，不将其改写成正式版。
- 本地模型 fixture 证明协议、工具和持久化链路，不代表真实 Gateway、外部模型质量或全部 Harness 组合已验收。
- Windows 受限 token 下的 Git Bash 外部程序仍有限制；验收的真实 Git Bash 工具路径使用显式授权的完整访问权限，不自动执行 ACL 修复。
- 组合、执行程序与工具审批共用同一设置页，但分别保持原有状态负责人；页面合并不改变会话权限、任务调度或 Auto Review 的放行规则。

### 升级

退出 DeepSeek Harness 后运行最新安装器，或使用 OPL 维护启动入口。更新失败保留当前安装，不替换运行中的 profile；官方桌面由 DeepSeek 原生机制更新。
