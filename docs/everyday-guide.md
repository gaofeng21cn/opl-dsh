## 在项目外聊天

想临时翻译一段文字、问一个和代码库无关的问题时，点 **新会话**，打开工作区选择器，选择列表里的 **× 不在项目中工作**。点这一整行就可以留在对话框中输入并发送。已有默认工作区时也可以这样选。如果任务需要读取或修改某个仓库的文件，就在同一处选择那个仓库，给这次任务明确的工作目录。

## 同时打开两个输入框时添加附件

在右侧栏打开可继续对话的子会话后，向窗口拖入文件可能会把附件添加到两个输入框。要只发给其中一个会话，先点目标输入框再粘贴文件，或使用该输入框的添加附件按钮。发送前看一下附件显示在哪一边。

## 修改已经发出的消息

假设你让模型“按月份汇总”，看到回复后才发现需要“按季度汇总”。等任务结束，把鼠标移到**自己发出的那条消息**，点右下角与复制并列的编辑图标。原文会回到输入框。改好后点发送；如果改变主意，点输入框里的关闭图标即可取消编辑。

这同样适用于支持消息编辑的外部执行引擎（Harness）。重发后，你仍在原来的侧边栏会话中，修改位置之后的聊天内容由新一轮接替。**之前的工具已写入的文件会保留。** 如果某次运行遇到限流，结束后也可以看原消息旁的图标。引擎需要能确认被编辑的是哪一条消息，具体支持范围见[编辑消息](stop-edit.md)。

### 编辑后为什么有两种轮数

打开 **设置 → 通用设置 → 轮次与步数**，选择统计范围。假设只发过一条消息，改写这条消息又发了一次，两次均执行完毕，每次各完成一步。

| 你想看什么 | 选择 | 对话下方显示 |
| --- | --- | --- |
| 当前看得见的这版对话有多长 | 当前对话 | 1 轮、1 步 |
| 连同改写前的那次，一共执行了多少 | 历史累计 | 2 轮、2 步 |

“历史累计”使用官方统计。“当前对话”只计算编辑后保留的轮次和步数。两种范围下，耗时与 token 用量均由官方或对应执行引擎提供。

## 按使用习惯调整通用设置

以下设置都能在 **设置 → 通用设置** 找到。

| 场景 | 设置 | 怎么用 |
| --- | --- | --- |
| 希望新对话沿用自己选过的权限 | <a id="remember-permissions"></a>**记住权限预设** | 开启后，在原生 DSH 会话中手动选择一次权限。这个选择会写入**官方默认权限**，以后新建会话也会使用它。 |
| Windows 任务栏里想一直看到应用名称 | <a id="window-title"></a>**固定窗口标题** | 开启后窗口固定显示 **DeepSeek Harness**。如果更喜欢用当前对话标题辨认窗口，关闭即可。 |
| 切去做别的事，希望跑完时收到提醒 | <a id="desktop-notifications"></a>**系统通知** | 开启后可先点 **测试通知**。正常使用时让 DSH 保持运行并切到后台，任务结束或失败会发系统通知。若通知中心有记录但没弹横幅，检查系统的横幅和勿扰设置。 |
| 想让 Windows 上的原生 DSH 用 Bash 执行命令 | <a id="git-bash"></a>**DSH 使用 Git Bash** | 装好 Git Bash，等活动任务停止，开启并保存设置，重启 OPL DSH。它作用于 standard、cordis、ptc 的 Shell 工具，minimal 的持久终端沿用官方配置。 |

系统通知是给电脑前的人看的。要让任务结果自动回到发起它的 Codex 聊天，在「设置 → 执行引擎与协作 → 跨引擎协作与外部 Codex 委派」配置任务完成通知，步骤见[从 Codex 委派任务给 DSH](codex-task-delegation.md)。

## 打开回复里交付的文件

比如请 DSH “把刚才的汇总保存成 CSV，并在回复里给我文件”。当回复以本地文件条目交付时，点文件名即可打开。下次翻到这条历史消息也能点击。文件入口指向原来的本地路径；如果文件已经移动，可以去新位置打开。

增强包通过官方公开 Conversation 扩展在普通 DSH 对话中识别 `deliver-assets` 文件标记并添加可点击条目，不放入折叠的执行过程区，也不会自动读取文件或执行命令：

- 只转换已闭合、位于代码块与行内代码之外、完全由本地 `file` 项组成的标记；支持 Windows 盘符、UNC 与 POSIX 绝对路径，以及单层 Markdown 反斜杠或尖括号实体转义。Windows 大小写与两种路径分隔符按同一文件去重，显示第一次提供的写法。
- 远程 URL、相对路径、其他媒体类型、残缺标记、代码示例和混入正文的块保持原文，不影响后续有效交付。
- 回复结束后，Chat 视图将已转换的文件标记从正文中收起并保留说明文字与文件入口；原始会话记录与复制内容不变。
- 查看历史记录会重新生成条目，不发送模型请求或执行历史工具；重试开始时旧条目隐藏，没有文件的回复不保留旧文件入口。

## 任务系统通知

OPL 通过官方 Desktop 的 Client 扩展提供基于标准 [Web Notifications 接口](https://www.electronjs.org/docs/latest/tutorial/notifications)的任务系统通知，不修改官方应用资源。开关默认开启，保存在当前 Desktop 用户数据目录；另一浏览器或另一数据目录独立设置。

- **触发时机**：DSH 窗口处于后台时，扩展观察到任务开始运行（或在界面加载、重连时通过官方会话列表确认仍在运行），随后收到实时结束或失败事件时发送通知。原生 DSH 与回写到官方会话的外部 Harness 共用官方 Agent 状态事件；内部子 Agent 不单独通知。
- **不补发边界**：前台结束不弹窗，之后切到后台也不补发；错误只产生一条失败通知；重读旧会话、断线、删除会话或晚到的列表读取都不会重新激活或冒充任务结束。DSH 必须保持运行与连接，完全退出或断线期间不补发通知。
- **内容与权限**：通知仅包含对话标题与“任务已结束”或“任务失败”（因官方公开状态事件不区分正常完成与手动停止，停止也显示“任务已结束”），不含回答、工具结果、错误详情或附件。点击通知请求唤回 DSH，不自动切换对话。系统拒绝通知时，后台任务不会自动申请权限，需通过「测试通知」或系统通知设置授权；设置中的“系统已接收通知”只表示原生接口已接受请求，实际展示仍受系统勿扰与横幅策略影响。

## 更新、超时与用量

- **更新 OPL 增强层。** 看到左下角 **↑ 更新**，点进去看可用版本和发行页中的更新摘要。兼容更新准备好后可点 **立即更新**；有任务运行时请先完成或手动停止。也可以在 **通用设置 → 更新 → 发现更新后** 选择 **仅提醒**、**退出后自动更新** 或 **空闲时自动重启更新**。页面分别列出官方 DSH 与 OPL 增强层的版本。更新各家执行引擎的入口在[模型与执行组合指南](model-harness-guide.md)。
- <a id="progress-timeout"></a>**为没有进展的任务设等待时间。** 在 **设置 → 执行引擎与协作 → 运行超时与队列限制** 打开 **启用 OPL 进展超时**，分别填写首次进展前、已有进展后持续安静多久才停止，然后点 **保存等待设置**。设置从新开始的执行轮次生效。只要持续有可识别的进展，任务可以运行超过这个时长。
- <a id="token-context"></a>**查看 token 和上下文窗口。** 想知道一轮用了多少 token，看对话下方的用量；想知道上下文还剩多少空间，有上下文圆环时点开看详情。外部引擎能提供的数据各不相同，带约数标记的值是估算，缺一项也不能据此当作用量为零。这里和「轮次与步数」选项可以分别看。
