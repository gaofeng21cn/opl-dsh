官方 DeepSeek Harness：`{{OFFICIAL_VERSION}}` · OPL 增强：`{{VERSION}}`

本版重新整理模型与 Harness 的组合规则，让内置组合只对应厂商官配，并为常用执行引擎补齐官方安装入口。

### 变更

- 自动组合改为来自维护的“Harness + 官配模型”表：DSH 只配 DeepSeek 自家模型，Codex、Claude、Grok Build、MiniMax、ZCode、Kimi、MiMo、Poolside、StepCode、Muse 只在对应厂商模型就绪时自动生成组合。
- OpenCode、Kilo、Pi 没有自己的模型，官配列表为空，不再自动生成组合；其他模型与执行引擎仍可在“添加执行组合”中自由配对，并明确显示为“自定义”。
- 清理旧版遗留的通用执行器自动组合和跨厂商自动组合；用户自己创建的同名组合保留，手动停用状态也不会被自动恢复。
- MiniMax、MiMo、StepCode、OpenCode、Kilo 和 Pi 在未安装时提供官方安装入口；安装结束后重新检测可执行文件和版本，首次检测到的真实路径会保存。Kimi Code 原有的 npm 安装包入口继续保留。
- MiniMax 安装后仍需运行官方 `mcode login`；OPL 不代替登录，也不读取账号凭据。未安装或未登录时，对应组合保持停用。
- “可启用但当前停用”的组合继续折叠，未就绪项不堆在主列表中。

### 验证

- Host/Client 类型检查、RPC、模块边界、格式、构建与自动测试：通过
- macOS arm64 与 Windows x64 未修改官方桌面隔离验收：通过
- 两平台验收同一增强包字节，覆盖 Client 设置、模型流、官方工具与重启恢复；源提交为 `{{SOURCE_COMMIT}}`
- 隔离 OFM 验收确认通用模型不会自动生成组合、手动组合可保存、官方安装入口可回读，用户停用后不会复开
- 联合清单与验收记录随 Release 提供；发布后逐一回读公开资产摘要

### 已知限制

- 自动组合只表示预设的官配关系，不代表模型当前在线可用；模型仍须出现在来源目录中并通过启动前检查。
- 手动跨厂商组合只是用户选择，不代表厂商官方支持或质量验收。
- OpenCode、Kilo、Pi 的安装入口使用其发布 npm 包；仍受本机 Node/npm 环境、网络和官方包可用性影响。
- 官方桌面及其候选阶段以以上实际版本为准；开发 API 依赖与桌面 feed 分别记录。
- 本地模型 fixture 证明协议、工具和持久化链路，不代表真实 Gateway、外部模型质量或全部 Harness 组合已验收。
- Windows 受限 token 下的 Git Bash 外部程序仍有限制；验收的真实 Git Bash 工具路径使用显式授权的完整访问权限，不自动执行 ACL 修复。
- 新功能的适用范围与限制见对应功能文档及提交；直接打开官方桌面不会运行外部 OPL 更新器。

### 升级

退出 DeepSeek Harness 后运行最新安装器，或使用 OPL 维护启动入口。更新失败保留当前安装，不替换运行中的 profile；官方桌面由 DeepSeek 原生机制更新。
