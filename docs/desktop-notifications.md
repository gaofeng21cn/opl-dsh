# 任务系统通知

OPL 在官方 Desktop 的 Client 扩展中提供任务系统通知，不修改官方应用资源。进入 **设置 → 系统通知**，可关闭任务通知或发送测试通知。开关默认开启，保存在此 Desktop 用户数据目录；另一浏览器或另一数据目录独立设置。

DSH 窗口在后台时，扩展观察到任务开始运行，或在界面加载、重连时通过官方会话列表确认它仍在运行，随后收到实时结束或失败事件，会调用系统通知。原生 DSH 与回写到官方会话的外部 Harness 共用官方 Agent 状态事件；内部子 Agent 不单独通知。前台结束不弹窗，之后切到后台也不会补发。错误只产生一条失败通知，不再产生普通结束通知；重新读取已结束的旧会话、断线和删除会话都不会冒充任务结束。加载或重连只恢复仍在执行的任务，不补发已经结束的任务通知；晚到的列表读取不能重新激活已结束或已删除的任务。

通知包含对话标题与“任务已结束”或“任务失败”，不包含回答、工具结果、错误详情或历史附件。官方公开状态事件不区分正常完成与手动停止，因此停止也显示“任务已结束”。点击通知请求唤回 DSH，当前版本不会自动切换到通知对应的对话。

DSH 必须保持运行与连接。扩展不会在应用完全退出时运行，也不会补发断线期间的结束事件。系统拒绝通知时，后台任务不会自动请求权限；用户可在测试按钮上主动申请，或在 Windows 的通知设置中允许应用。勿扰模式与系统通知策略可能隐藏弹窗；设置中的“系统已接收通知”只表示原生通知接口已接受请求。

此实现使用 Electron 支持的标准 [Web Notifications 接口](https://www.electronjs.org/docs/latest/tutorial/notifications)。官方 Desktop 0.2.0-rc.2 的隔离 Windows profile 已验证设置显示、默认开启、测试通知 `onshow`、关闭及页面重载后保存，并用真实 MiniMax 完成与原生 DSH 失败事件验证系统通知 `show`。CLI 派发的未打开会话已验证后台失败通知；受控无密钥模型适配器配合真实官方 Agent 生命周期，已验证界面重载后继续运行的任务在后台结束时发送系统通知，不代表真实模型验收。本机安装与安装后验证单独进行；不同 Windows 的通知策略可能隐藏弹窗。
