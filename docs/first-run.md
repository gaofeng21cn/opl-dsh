# 首次启动与登录

OPL DSH 使用官方 DeepSeek Harness 桌面，在应用内提供统一的账户选择：OPL Gateway、DeepSeek 官方、稍后登录。首次设置完成后，后续启动直接进入工作区。

选择 OPL Gateway 后，在当前弹窗输入邮箱和密码。插件沿用已有账户服务按账号权限申请或复用各分组密钥。优先选择 DeepSeek 分组的 `deepseek-flash`；仅有其他分组时，选择该账号已经配置且可用的模型。缺少某个分组不会阻止其他分组使用，请求不会在失败后改发到其他分组。

Windows 登录表单的“记住密码”默认关闭。勾选并成功登录后，邮箱与密码保存在当前用户的 Windows 凭据管理器条目 `OPLDSH:Gateway:RememberedLogin`；页面只回读保存状态与邮箱，点击登录时才由 Host 读取密码。取消勾选清除保存项，退出账号保留已记住的密码。其他平台不提供此选项，不回退到明文文件。

选择 DeepSeek 官方后，可以发起官方账户授权，或在当前弹窗填写官方 API Key。官方账号仍使用官方授权页面；授权完成后自动回到应用内的工作区。OPL 不接收 DeepSeek 账号密码。

“稍后登录”只需选择一次，会保存为已完成首次设置。之后可从设置中连接账户。首次页面不显示内测声明、用途问卷或其他 OPL 应用的旧账户。

## 与官方桌面的衔接

启动器读取实际官方桌面版本。官方原生欢迎窗口尚无第三方登录插件入口时，启动器通过仅父子进程可用的 Chromium 管道调用该窗口已有的 `dshWelcome.skip()`，然后由增强插件在官方主窗口中显示账户选择。未来版本如果没有这个接口，会保留官方欢迎窗口；不会伪造凭据或跳过模型调用的身份验证。

启动器不监听 TCP 调试端口，不修改 `app.asar`、签名资源或官方 Agent 循环。管道只用于本次启动的欢迎窗口衔接。遇到首启接口不可用时，保留官方欢迎窗口并给出操作提示。升级官方版本时须重新验收这一小段版本相关的接口。

首次设置状态由 Host 的 `opl-suite` 配置保存；登录和密钥仍由各自的官方/OPL 账户服务管理。设置 RPC 使用官方 Connection 的受认证路由；模型选择保存成功后才标记完成。已配置账户的安装升级时保留状态。

## Linux CLI/Web 首启

Linux 使用 `launch-opl-linux.sh` 启动独立的 `opl-linux` profile。启动器在 `127.0.0.1:4180` 监听，并在标准输出打印带认证参数的完整地址；请打开该完整地址，不要复用其他 profile 的 token 或当前 `web` 页面地址。页面中的 OPL 账户选择、Gateway 登录和官方账号授权仍由同一组 Host/Client 服务处理，不经过 Electron 欢迎窗口。

地址丢失或页面返回 `401` 时，先从启动该 profile 的终端正常结束 Host，再运行启动器取得新的认证地址。不要使用无认证参数的地址反复尝试，也不要读取其他进程的控制文件。若需要诊断启动失败，请检查启动器输出。

## 验证范围

Linux CLI/Web 的 Host、认证页面、控制 RPC 可与官方桌面分开验收；这些结果不属于 Electron Desktop 资格。增强包使用独立自动更新入口，不分发自有桌面壳；官方桌面版本变化后须在隔离桌面重新验收欢迎窗口衔接、登录表单、跳过和重启恢复，官方账号完整授权仍需真实账号完成。

## 在 Codex 中使用 OPL 网关

在 **设置 → OPL Gateway** 登录 OPL。账号有“OpenAI 协议”分组权限时，展开 **配置外部 Codex**。即使该分组在 DSH 中未激活，也可以单独配置 Codex。Windows 用户选择运行 Codex 的环境。使用 WSL 时，确认所选发行版。macOS 会自动选中本机。

点击 **一键配置**。DSH 向网关申请或复用 Codex 专用密钥，将其保存在目标环境的凭据库中。Windows 原生使用 Windows 凭据管理器，macOS 使用系统钥匙串，WSL 使用该发行版的 Secret Service。支持的 WSL 发行版缺少依赖时，点击 **安装钥匙串并配置** 同意安装。有需要时，按系统提示解锁钥匙串。

看到配置成功后，重新打开所选环境的 Codex。初始模型为 `gpt-6.2-sol`，以后可在 Codex 中切换模型。

若检测到文件中的旧凭据或其他登录，配置会停止并保留原登录。需要切换时，在对应环境的 Codex 中退出旧登录再重试。
