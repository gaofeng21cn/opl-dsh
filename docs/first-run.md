# 首次启动与登录

OPL DSH 使用官方 DeepSeek Harness 桌面，在应用内提供统一的账户选择：OPL Gateway、DeepSeek 官方、稍后登录。首次设置完成后，后续启动直接进入工作区。

选择 OPL Gateway 后，在当前弹窗输入邮箱和密码。插件沿用已有账户服务申请或复用 DeepSeek 与 Codex 分组的密钥，并保存默认模型 `deepseek-flash`（DeepSeek-V4.1-Flash）。默认通道可用即可进入；备用通道暂不可用时不阻塞使用。

选择 DeepSeek 官方后，可以发起官方账户授权，或在当前弹窗填写官方 API Key。官方账号仍使用官方授权页面；授权完成后自动回到应用内的工作区。OPL 不接收 DeepSeek 账号密码。

“稍后登录”只需选择一次，会保存为已完成首次设置。之后可从设置中连接账户。首次页面不显示内测声明、用途问卷或其他 OPL 应用的旧账户。

## 与官方桌面的衔接

启动器读取实际官方桌面版本。官方原生欢迎窗口尚无第三方登录插件入口时，启动器通过仅父子进程可用的 Chromium 管道调用该窗口已有的 `dshWelcome.skip()`，然后由增强插件在官方主窗口中显示账户选择。未来版本如果没有这个接口，会保留官方欢迎窗口；不会伪造凭据或跳过模型调用的身份验证。

启动器不监听 TCP 调试端口，不修改 `app.asar`、签名资源或官方 Agent 循环。管道只用于本次启动的欢迎窗口衔接。遇到首启接口不可用时，保留官方欢迎窗口并给出操作提示。升级官方版本时须重新验收这一小段版本相关的接口。

首次设置状态由 Host 的 `opl-suite` 配置保存；登录和密钥仍由各自的官方/OPL 账户服务管理。设置 RPC 使用官方 Connection 的受认证路由；模型选择保存成功后才标记完成。已配置账户的安装升级时保留状态。

## 验证范围

已在未修改的官方 Apple Silicon 桌面验证：应用内弹窗、Gateway 登录页呈现、官方授权发起与取消、官方 API Key 输入界面、一次跳过进入工作区、重启不再提示。官方账号完整授权需要用户自己的账号，本轮未完成该外部登录。Windows x64 已在未修改的官方桌面验证安装、应用内首启、Gateway 登录页呈现、稍后进入工作区及 Codex 协作设置。增强包使用独立自动更新入口，不分发自有桌面壳；官方桌面版本变化后需重新验收插件接口。
