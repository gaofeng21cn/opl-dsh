# OPL DSH 会话清理

这个 Skill 只处理用户明确指定的 DSH 数据范围。它把“找出候选”和“删除已指定对象”分成两条流程：标题、轮次数、失败状态和 `test`/`owned` 前缀只能帮助发现候选，不能单独证明可以删除。

## 删除模式

- 默认使用 `recycle`：将精确文件或目录移入 Windows 回收站，逐项核验回收内容、原路径和 SHA-256，并保留恢复清单。
- 只有用户明确要求永久删除时才使用 `permanent`。永久删除前仍必须生成并复核清单；没有可靠的当前存储删除协议时停止，不把“删除列表行”或“隐藏会话”称为永久删除。
- 目标可以是精确会话 ID、精确外部 Harness ID、明确的工作区成员集合或归档集合。模糊标题、模糊路径、全量“看起来像测试”的规则必须先转为清单并等待用户确认。
- 用户指定“清空已归档”时，使用本次运行的官方 `WorkspaceRegistry.archivedSessionIds` 作为唯一目标来源。先冻结该集合为 `archivedTargetIds`，再读取当前 Session 列表建立 `protectedSessionIds = allSessionIds - archivedTargetIds`。不能根据侧边栏筛选结果、标题、时间或“删除候选”猜测归档状态。
- “清空已归档”每次只处理冻结清单中的 ID。归档目标若有未归档子会话/分支、保留任务、未知关联、活动状态或无法完整读取的日志，就从本批目标中排除并报告。每个未归档会话及其外部记录都属于保护范围。

## 固定流程

1. **定位当前数据根。** 读取当前安装回执、公开 Session/Task 接口和当前 Skill 配置，确定实际 `DSH_HOME`、profile、Session 存储、Workspace 登记和外部 Harness 记录目录。不能沿用历史绝对路径，不能读取或输出 `control.json`、凭据或完整环境。
2. **盘点并建立清单。** 为每个目标记录 ID、实际路径、文件集合、大小、SHA-256、归档/工作区归属、父子/种子/分支关系、TaskFeedback 引用、外部 Harness 记录和索引基线。完整读取所有可读日志代次；压缩日志或迁移 successor 缺失时保留目标。“清空已归档”另记录冻结的 `archivedTargetIds`、完整 `protectedSessionIds` 及每个受保护会话和外部记录的文件哈希。
3. **分类并冻结。** 运行中、排队中、等待审批/输入、状态未知、仍被开发派活或保留任务引用的对象默认保留。清理前确认相关原生与外部任务静止；只退出本轮由 Codex 为调试启动的准确 Desktop 实例，不能按进程名批量结束其他实例。清单建立后出现文件、索引或任务漂移就停止并重建清单。
4. **核对关联闭包。** 原生会话与外部 Harness 记录按真实 `nativeSessionId` 关联，不按相似标题配对。若目标有子会话、父会话、TaskFeedback、消息编辑/恢复意图、附件或其他保留会话引用，必须由用户明确授权整个关联闭包；否则保留目标。工作区登记可移除，项目目录和会话执行过的文件默认保留。
5. **执行并记录进度。** 每次只操作清单中的精确路径，拒绝符号链接、junction、根目录和路径穿越。Windows 回收站模式使用 `Microsoft.VisualBasic.FileIO.FileSystem` 的 `SendToRecycleBin`，不用 `rm`、`Remove-Item` 或通配符。永久模式仅在当前 provider 的删除协议、所有 owner/reader、代际日志、迁移临时文件、索引、附件引用和重启 tombstone 都能逐项验证时执行；否则报告阻塞原因并保持数据不变。
6. **同步索引。** 回收或永久删除成功且逐项验证后，才从 Workspace 的成员、归档、置顶和搜索/投影登记中移除精确 ID。更新前比较索引字节摘要；发生漂移立即停止。不要顺带删除 TaskFeedback 台账、迁移标记、项目目录或其他未知记录。对“清空已归档”，写索引时只能移除冻结目标 ID；所有受保护 Session ID 和相应 Workspace/外部记录必须原样保留。
7. **验收。** 重新读取公开列表，确认目标不再出现；对保留会话做一次可读性检查；确认没有空工作区登记、打不开的幽灵条目、残留外部记录或目标 ID 的缓存引用。执行“清空已归档”时必须再次计算归档集合，并证明所有原 `protectedSessionIds` 仍存在、未归档状态未变且文件哈希与基线一致；发现任何受保护数据变化就不得报告成功。需要启动验证时只启动一个实例；用户要求保持退出时记录未启动。
8. **交付报告。** 报告原生会话、外部记录、工作区登记和项目目录各自的数量，说明采用的模式、回收/恢复材料位置、保留项数量、索引实际变化和启动验证结果。不要粘贴会话正文或凭据。

## 永久删除的当前边界

官方 `SessionPersistence` 当前只公开创建、打开、刷新、统计和列举；它没有删除/保留 API。官方 JSONL provider 还可能存在写 owner、跨进程 lease、历史代际、迁移 successor、查询缓存和共享附件。因此在未发现官方删除协议前，永久模式必须停止并说明“上游接口不足”。不得直接 unlink 物理日志来绕过这些生命周期约束。

如果以后官方提供删除接口，仍须验证：活动 admission 被阻断、所有 owner 已关闭、所有代际与临时文件已处理、Workspace/搜索/投影/附件引用已同步、删除事件已广播，以及重启和冷加载不会复活目标。把这些条件写入本轮清单后才能启用永久模式。

## 恢复与失败

部分回收或索引写入失败时保存已完成项和原始索引快照，停止继续处理；不能重跑整批或用旧清单覆盖新状态。恢复前退出目标 Desktop，按精确 ID 合并恢复文件与索引，原位置已有变化时不覆盖。回收站模式保留恢复路径和哈希；永久模式不承诺可恢复。

本 Skill 不会自动清空回收站、删除项目目录、删除 Codex 普通聊天或修改生产 ACL。它也不把“归档”当作删除：归档只是官方可恢复的隐藏状态。

## 性能实现

预览与执行前各读取一次完整快照；执行后的检查只比较冻结清单中的文件元数据、引用目录清单和索引摘要，不重复解压全部历史日志。执行阶段只在开始、索引提交前和结束时检查桌面进程，避免按目标重复调用系统进程查询。
