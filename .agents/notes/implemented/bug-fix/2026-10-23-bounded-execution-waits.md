# 执行无进展等待

Status: implemented

## Problem

CLI 可能收到上游错误后继续重试，或只发送心跳而不结束请求。首次输出之后移除的计时器无法约束后续停滞；请求级重试也可能重新开始等待预算。

## Decision

执行插件统一配置首次进展、连续无进展和总执行时长。排队不计入执行时间；正文、思考与工具事件表示进展，空更新和传输心跳不表示进展。工具执行暂停无进展计时，总执行时间继续累计；公开人工等待暂停两种计时。重试共享当前轮次预算，结束后释放计时器。

排队提示注册到 `conversation.input.right` 列表，使用独立条目标识；编辑消息独占 `conversation.input.activity` 单项位置。重复注册单项位置会使执行插件加载失败，连带撤销模型选择控件；注册检查使用官方 SlotCore 验证三者可以同时存在。

外部 Harness 截止后先关闭 ACP 通道并拒绝在途请求，再等待自有进程退出；迟到输出和成功回执不能改写失败。原生请求通过公开流和 Agent 生命周期接口取消并结束流消费；不重发请求、不更换模型，不从超时推断认证、限额或具体 HTTP 错误。已知上游错误仍立即按结构化诊断返回。

## Verification

聚焦测试覆盖首次与空闲截止、重试总预算、工具和人工等待、手动取消、晚到输出、挂起流清理及 ACP 子进程退出。真实服务的可用性与响应速度另行验收，超时本身不证明服务故障原因。
