# OFM external Harness routes

OFM owns model discovery, credentials, channels and its forwarding listener. The enhancement registers explicit model/Harness pairs and resolves each execution route through the owner's public interfaces. An installed CLI and a listed model establish local readiness; they do not establish that the upstream accepts a live request.

External adapters verify model, permission and Shell observations before sending a prompt. Unsupported restricted access is refused. Connection replacement or source withdrawal invalidates an in-progress launch. CLI-default thinking stays unset until the official CLI advertises the choice; generic chat-model defaults must not become external CLI settings.

The ordinary model picker stores the selection without creating an external task. The first prompt binds the Session's current permission. A legacy zero-turn binding can be refreshed, but an admitted external turn retains its recorded permission and review mode.

JEV and Content Safety remain outside the coding-model menu. GPT-OSS 20B is explicitly paired with Codex. Live availability remains dependent on the selected OFM channel; protocol fixtures, CLI probes and Git Bash checks do not replace that evidence.

Global new-conversation actions may create an ungrouped Session. Workspace-targeted actions retain their explicit Workspace. Message-edit state belongs to a Session and survives callback replacement without clearing the current edit selection.

Compiled Pi and Step test bridges use independently allocated roots. esbuild returns output bytes to Node for filesystem writes, which supports Windows hosts that permit Node writes but refuse writes from the esbuild helper executable.

Pi and Step bridges quote the complete Windows CLI argument vector at the child launch. The outer Node bridge retains Node's normal argument quoting. All packaged bridges follow the requested build output directory, including the native Harness bridge.

Pi and Step transport-success turns require an answer or completed tool result. Thinking and failed tools cannot become a successful completion. Adapter tests separate Windows execution from portable route and permission checks; subprocess cases have explicit deadlines that include CLI discovery and startup.
