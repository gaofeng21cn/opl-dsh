# Agent Note: 精确 DSH 会话清理 Skill

Status: implemented

## Problem

一次性测试会话、外部 Harness 记录和空工作区可能互相引用。只移走日志或列表行会留下打不开的会话、空目录或可复活的索引；每次临时清理也容易重复扫描和误删开发派活。

## Decision

OPL 套件随安装包提供 `opl-dsh-session-cleanup` Skill。它要求先按用户指定范围建立会话、任务、父子、Harness、工作区和索引清单，再冻结活动、核对关联闭包、逐项执行回收并验证哈希，最后重读列表和保留会话。默认模式使用 Windows 回收站并保存恢复材料；升级旧版同名 Skill 时先备份旧目录。

永久删除必须由用户明确选择，并且当前存储 provider 提供完整的删除和生命周期协调协议。官方 rc.3 只有 `SessionPersistence.create/open/flush/stat/list`，没有持久删除 API；因此 Skill 在当前版本遇到永久删除请求会停止，不直接 unlink JSONL、绕过 writer lease 或手改索引假装删除成功。

## Alternatives considered

**直接删除日志和索引。** 放弃，因为无法协调活动 writer、历史代际、查询缓存、附件和重启恢复，会重现残留打不开记录。

**只增加 DSH 设置里的删除按钮。** 放弃，因为当前官方 Host 没有对应的持久删除接口；按钮只能隐藏或删索引，不能兑现永久删除语义。

**继续使用每次临时脚本。** 放弃，因为脚本容易携带旧路径和固定候选，不能稳定复用用户指定范围、关联核对和漂移检查。

## Consequences

清理请求可以直接复用 Skill，用户只需指定会话、工作区或关联范围以及回收站/永久模式。隔离合成测试覆盖精确目标、活动拒绝、开发会话保留、外部记录配对、文件漂移拒绝和回收哈希核验；生产数据仍需要按当前公开接口盘点，永久删除要等待官方支持。
