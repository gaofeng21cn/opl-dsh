# 外部 Harness 的空完成

外部 Harness 返回 `end_turn` 后，套件要求本轮存在非空正文或至少一个已完成的工具结果。没有专属完成判定的适配器复用 `acceptVisibleCliResult`；MiMo 等适配器保留自己的具体诊断。推理、空白正文、待执行或失败工具不算交付，拒绝结果在任务记录与通知读取前落为失败，不重发请求。

用户停止标记在持久保存和子任务等待之前建立；当前轮次即使随后收到 CLI 的 `end_turn`，也保持 `cancelled`，原始 stopReason 单独保留。停止操作只作用于调用时捕获的轮次，不能因等待而取消后续轮次。

Codex 的 agentMessage 正文可来自增量、item/completed 或 turn/completed.items；按消息身份合并实际文本，只补未交付尾部。完成事件不含正文时不能据结束状态生成回答。

官方 Kimi Code 的真实 OFM 调用曾在多次模型请求失败后返回空 `end_turn`。只对部分适配器启用空结果检查会把同类失败记成完成。该检查依据实际交付内容，不从空回复猜测 HTTP 状态、登录状态或上游原因，也不把有正文但仍运行的任务提前结束。

`tests/execution/harness.spec.ts` 通过真实 ACP 子进程验证空回复、仅推理、空白回复、失败及待执行工具的拒绝、持久状态和单次请求；完成工具无需正文仍可成功。MiMo 测试保留专属诊断。

ACP 错误保留套件固定的请求阶段及安全的结构化诊断，不回显未知方法或提供方消息。进程退出和请求超时保留为受控传输错误，不能在任务落盘时折叠成安装或登录提示；未分类的内部错误保持原因未知，不能据此断言认证失败。
