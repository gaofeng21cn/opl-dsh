# OFM 官方 CLI 终态与 Responses 字段

Pi 和 Step 的 `agent_settled` 不携带请求结果；桥接器保存官方 `message_end` 与 `auto_retry_end` 的最终失败类别，在完全结算时拒绝失败轮次。成功重试清除先前失败，取消和新轮次清空旧结果。错误正文只在分类器内读取，不返回或持久化供应商原文；部分正文不替代官方成功终态。

Muse 1.4.7 要求 Responses 文本 delta 的 `content_index`、失败对象的 `code`，以及工具参数完成事件与已广播 `item_id` 一致。OFM 2.1.0 的转发器缺少前两项，并可能在最终输出中更换调用身份。OPL 中继补齐缺失字段，按输出索引关联已广播工具项，保留上游已有字段和失败状态。

真实官方 CLI 与已安装 OFM 转发器在隔离目录中的受控成功、工具和拒绝流用于验证协议；它们不代表联网模型可用性。免费额度、渠道拒绝和上游断流仍作为真实失败处理，不通过伪造结束或自动重发掩盖。
